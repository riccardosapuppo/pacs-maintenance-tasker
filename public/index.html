PACS Maintenance Tasker

A job that frees space on a medical image archive by deleting studies nobody needs any more. There is no undo.

— the claims, below

1 · The archive, and what a run would do to it

Four hundred and nine invented studies, with real folders in a temporary directory. A dry run decides and changes nothing; a real run does exactly what the dry run said it would, because it is the same decision.

2 · Every study, and why

A run that says 88 refused and cannot break it down is a run nobody can act on: half of those might be a broken sync somebody should fix today and the other half studies that are simply not old enough.

3 · Make the two mistakes on purpose

Both switches default to the safe setting, and neither of them changes which studies go — only how. Turn the disk failure on, pick the other order, and run it: the orphan count above is folders that were on the disk a second ago and that nothing will ever look for again.

4 · Three claims that can fail

Not a benchmark. Nothing here is a number that means fast. Each claim is about being right on an operation nobody can take back, and each one carries what being wrong would have cost. These are what npm run measure prints, computed the same way.

Every study, patient, booking and report here is invented. No clinic, no patient and no real archive appears anywhere in this repository. The files this deletes are written by it, into a temporary folder, and go when the process stops.
